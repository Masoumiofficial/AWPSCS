## 1. معماری فعلی داده‌ها

### 1.1 بازدید (views)
- **کلید:** `views` (بدون پیشوند `_`، سفارشی قالب)
- **محل:** `wp_postmeta` → `meta_key='views'`
- **نوع:** INT UNSIGNED (ذخیره به‌صورت string)
- **نویسنده:** احتمالاً در `functions.php` قالب، هر بار `single.php` باز می‌شود: `update_post_meta($id,'views', ++$views)`
- **مشکل:** هیچ جدول جداگانه‌ای نیست؛ کش می‌تواند شمارش را از دست بدهد.
- **یافته:** در مخزن فعلی هیچ PHP یافت نشد؛ لذا فرض امن: **direct**.

### 1.2 امتیازدهی kk Star Ratings
بررسی نسخه 5.4.10.5 (WordPress.org + GitHub surveywp/kk-star-ratings + مقالات WP-Evo/StackExchange):

| شاخص | کلید meta | گزینه | توضیح |
|------|-----------|-------|-------|
| تعداد رأی | `_kksr_casts` | — | COUNT(*) |
| مجموع امتیاز | `_kksr_ratings` | — | SUM(rating) بر مبنای 5 ستاره |
| میانگین legacy | `_kksr_avg` | — | برای سازگاری نسخه‌های <3.0 نوشته می‌شود؛ منبع حقیقت نیست |
| تعداد ستاره | — | `kksr_stars` | پیش‌فرض 5، قابل تنظیم تا 10 |

- **جدول اختصاصی:** ندارد. فقط postmeta.
- **ذخیره رأی:** هر رأی با IP در `wp_options` یا جدول `kksr_ips` قدیمی؛ در 5.x حذف شده و فقط IP hash در transient.
- **فرمول نمایش:** `score = round( ratings / casts /5 * best , 1 )` — `best` از `kksr_stars`.
- **هوک رأی:** `do_action('kksr_vote', $id, $rating)` و `do_action('kksr_rate', ...)` در نسخه‌های قدیمی.
- **API رسمی:** ندارد. فقط توابع `kk_star_ratings()` و کلاس `Bhittani\StarRating\KKSR`. لذا آداپتور اختصاصی لازم است.

## 2. منبع اصلی هر سه شاخص

| شاخص | منبع حقیقت | قابل اعتماد؟ | ریسک |
|------|------------|-------------|------|
| views | `meta_key=views` | متوسط (قابل دستکاری) | کش، افزونه‌های شمارش موازی |
| rating count | `_kksr_casts` | بالا | Race condition تا 5.4.6 (CVE-2023-4642) |
| rating avg | محاسبه از `_kksr_ratings/_kksr_casts` | بالا | ناسازگاری legacy `_kksr_avg` |

## 3. خطرهای ناسازگاری

1. **قالب فقط views را می‌خواند:** تفکیک واقعی/مدیریتی ممکن نیست → راهکار: آرشیو `_apex_real_views` + تاریخچه.
2. **kk بدون API رسمی:** نوشتن مستقیم متا اگر فرمول رعایت نشود، avg دروغ می‌دهد → آداپتور با ولیدیشن سازگاری.
3. **کش:** WP Rocket/LiteSpeed کش صفحه را نگه می‌دارد؛ ستاره قدیمی نمایش داده می‌شود → purge خودکار.
4. **ترافیک کم → WP-Cron تأخیر:** جهش یکجا به‌جای مرحله‌ای → مستندسازی Cron واقعی.
5. **همزمانی:** دو مدیر همزمان → قفل DB.
6. **رأی واقعی همزمان با برنامه:** اعداد پرش می‌کند → توقف خودکار به needs_review.

## 4. راهبرد پیشنهادی (اجراشده)

- **کشف خودکار:** نمونه‌برداری از postmeta برای یافتن کلیدهای واقعی، نه فرض کور.
- **نوشتن امن:** تراکنش + ولیدیشن + تاریخچه + execution_id.
- **زمان‌بندی:** WP-Cron هر 5 دقیقه + جدول schedules + calculate_next_step خطی.
- **ضد نوسان:** max_step, max_percent, threshold 20% برای کاهش.
- **امنیت:** capability+nonce+prepare+lock.
- **بدون حذف آمار:** غیرفعال‌سازی فقط کرون را پاک می‌کند.
